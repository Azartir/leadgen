# Российская B2B-охота

Цель профиля `ru_b2b` — собрать первичный список независимых локальных компаний в России, которым потенциально можно предложить разработку сайта, улучшение сайта или автоматизацию обработки заявок.

## Запуск

    python -m leadgen --list
    python -m leadgen --vertical ru_b2b --market stavropol_ru --sources osm --out stavropol_b2b
    python -m leadgen --vertical ru_b2b --market "Ростов-на-Дону, Россия" --sources osm --out rostov_b2b
    python -m leadgen --vertical ru_b2b --market moscow_ru --sources osm --out moscow_b2b

Результат — CSV для импорта в CRM и XLSX с приоритетом, баллом, причиной попадания и заготовкой первого сообщения на русском языке.

## Что изменено для российского рынка

- Русскоязычные названия полей, причины оценки и заготовки первого контакта.
- Пресеты городов: Москва, Ставрополь, Ростов-на-Дону и Краснодар; можно передать произвольное русское название города.
- Приоритет независимых компаний, а не крупных сетей.
- Скоринг учитывает отсутствие собственного сайта, ссылку на соцсеть/каталог вместо сайта, недоступный сайт, отсутствие HTTPS, мобильную адаптацию, скорость загрузки и доступность телефона/email в исходных данных.
- Сообщение — только черновик для ручной проверки, не автоматическая рассылка.

## Ограничения источников

На текущем этапе сбор идёт из OpenStreetMap через Overpass и, если выбран, Overture. Это не равно полному покрытию российского рынка: карточки могут отсутствовать, контакты могут быть устаревшими, а качество тегов различается по городам. Профиль не обходит Яндекс Карты или 2ГИС и не обещает доступ к их данным без ключей. Для следующего этапа нужны отдельные легальные коннекторы или импорт выгрузок, разрешённых условиями соответствующего источника.

## Практический рабочий процесс

1. Начните с одного города и одного источника (`osm`), чтобы контролировать объём.
2. Откройте лиды уровня A, проверьте карточку компании и сайт вручную.
3. Добавьте в CRM дату проверки, ответственного, статус контакта, источник и результат.
4. Перед повторным запуском используйте имеющуюся выгрузку CRM для дедупликации, если GUI/CLI workflow это поддерживает.
5. Не считайте балл доказательством потребности: это эвристика для сортировки, а не подтверждённый спрос.

## Юридическая и операционная гигиена

- Используйте только необходимые деловые контактные данные и соблюдайте условия источников.
- Не включайте персональные контакты сотрудников в публичный Git-репозиторий; выгрузки держите локально и исключёнными из Git.
- Не запускайте массовые сообщения автоматически. Проверяйте основание, адресата и требования применимого законодательства о персональных данных и рекламе.
- Уважайте отказ от дальнейших контактов и ведите список исключений.

Профиль — стартовая адаптация для России, а не готовая интеграция с реестрами юрлиц. ИНН/ОГРН, проверка статуса ООО/ИП, выручка, штат, госзакупки, Telegram и CRM-интеграции не извлекаются автоматически этой версией.


## Подключение картографических API

- 2ГИС: `DGIS_API_KEY` (или `TWO_GIS_API_KEY`); демо-ключ действует ограниченное время и имеет лимиты.
- Яндекс: `YANDEX_MAPS_API_KEY` и явное разрешение обработки через `YANDEX_MAPS_ALLOW_PROCESSING=1` в CLI либо чекбокс в интерфейсе. Не включайте источник, если лицензия не разрешает такую обработку.
- После объединения источников экспорт содержит поля «Все источники», «Источников совпало» и «Расхождения». Это автоматическая сверка, а не гарантия достоверности.
